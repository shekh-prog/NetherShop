# NetherShop

Telegram-магазин ресурсов Minecraft на aiogram 3 + SQLAlchemy async + Alembic.

## Запуск

1. Нужен Python 3.12+.
2. Создай бота через BotFather и скопируй токен.
3. Скопируй `.env.example` в `.env`, заполни `BOT_TOKEN`.
   `ADMIN_ID` уже установлен в `7475644552`.
   **Локальный запуск:** раскомментируй в `.env` строку `DATABASE_URL=sqlite+aiosqlite:///./nethershop.db`.
   Без неё база по умолчанию лежит в `/app/data/nethershop.db` (путь рассчитан на хостинг/контейнер,
   на обычном компьютере такой папки нет).
4. Установи зависимости:

   ```bash
   python -m venv .venv
   # Windows:
   .venv\Scripts\activate
   # Linux/macOS:
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

5. Запусти бота:

   ```bash
   python -m app
   ```

   Миграции Alembic бот применяет сам при каждом старте (`alembic upgrade head` вручную не нужен).

   На хостинге можно запускать `python main.py`: он создаёт `/app/data`, ставит зависимости и вызывает
   тот же `python -m app`.

## Возможности

- Регистрация Minecraft-ника при первом запуске.
- Категории и пустой каталог изначально.
- Корзина хранится в БД и привязана к `telegram_id`: не сбрасывается при смене категории, смене ника, `/start` и перезапуске бота. Один товар — одна строка; количество «устанавливается», а не прибавляется. Карточка товара открывается с уже выбранным количеством, кнопки −10/−5/−1/+1/+5/+10, «Очистить всё» (с подтверждением).
- Цены показываются в алмазах и алмазных блоках (1 знак после запятой).
- Выбор пункта выдачи перед оформлением.
- Заказы и история клиента. Оплата — алмазами в сундуке (см. раздел «Оплата заказов» ниже).
- Статистика выручки за последние 7 и 30 дней и за всё время (учитываются заказы с подтверждённой оплатой; после закрытия заказа остаются только сумма и дата продажи) и сумма, которая ещё ждёт оплаты.
- Логотип в интерфейсе магазина: положи `logo.png` в папку `assets` (путь `assets/logo.png`).
- Роли: клиент, исполнитель, глава.
- Исполнитель принимает заказ, бросает его, отмечает готовым или отменяет с причиной.
- Глава управляет товарами, пунктами выдачи и персоналом.
- Отмена исполнителем физически удаляет заказ, но перед этим клиенту отправляется уведомление.
- Для голов каждый раз запрашивается ник и подтверждение предупреждения.

## Команды главы

- `/add_worker <telegram_id>`
- `/delete_worker <telegram_id>`
- `/add_admin <telegram_id>`
- `/delete_admin <telegram_id>`

Первый глава задаётся через `ADMIN_ID` в `.env`.

## Управление каталогом

В меню главы: «Кастомизировать» → товары / пункты выдачи.
Для товара указываются название, категория, количество в порции, цена в алмазах и необязательное описание.

## Важные замечания

- Один заказ может быть закреплён только за одним исполнителем. Это обеспечивается транзакцией и блокировкой строки там, где СУБД поддерживает `FOR UPDATE`; SQLite дополнительно использует атомарный `UPDATE ... WHERE status='pending'`.
- `Заказ готов` переводит заказ в статус `ready` («Прибыл в пункт выдачи»).
- «Бросить заказ» снимает исполнителя и возвращает заказ в `pending`.
- При отмене заказ удаляется из основной таблицы; уведомление клиенту содержит состав заказа и причину. Для аудита можно позже добавить отдельную таблицу событий.
- Корзина лежит в таблице `cart_items` (миграция 0004). Цены берутся из каталога в момент просмотра, а скрытые из каталога товары убираются при оформлении.
- Состояния диалогов (FSM) хранятся в таблице `fsm_states` (миграция 0006) и переживают перезапуск бота.
- Оформление заказа — одна транзакция: заказ создаётся и корзина очищается вместе, двойное нажатие не даёт дубль.
- SQLite подходит для одного экземпляра бота. При нескольких процессах лучше перейти на PostgreSQL, изменив `DATABASE_URL`.


## Новые функции (миграция 0003)

При запуске бота Alembic автоматически применяет миграции до `head`. Миграция 0003 добавляет сроки блокировки игроков, список голов, недоступных для заказа, и связь завершённых продаж с покупателями. Старые продажи остаются в общей статистике, но не входят в персональные расходы, так как исторически не содержат ID покупателя.

Команды глав (администраторов):
- `/make_unsellable_head <nickname> [months]` (старое написание `/male_unsellable_head` тоже работает) — запретить продажу головы на указанное число месяцев; без срока — навсегда.
- `/make_sellable_head <nickname>` — снова разрешить заказ головы.
- `/list_unsellable_heads` (старое `/list_unsallable_heads` тоже работает) — список защищённых голов и оставшихся дней.
- `/ban <nickname> [days]` — заблокировать игрока на дни или навсегда.
- `/unban <nickname>` — снять блокировку.
- `/list` — список зарегистрированных игроков (отсортирован по сумме завершённых покупок); у каждого кликабельный `@username`, а если username скрыт — ссылка на профиль.
- `/delete <nickname>` — полностью удалить игрока из базы (его заказы удаляются, статистика продаж сохраняется). Ему придётся заново зарегистрироваться через `/start`. Нельзя удалить себя и главного администратора из `ADMIN_ID`.
- `/ban <nickname> [days]` без срока банит навсегда.

Профиль доступен всем пользователям через кнопку «Профиль». В профиле видны потраченная сумма (по заказам с подтверждённой оплатой) и текущий долг за заказы, ожидающие оплаты.

## Ники

Minecraft-ник: 2–32 символа, только латиница, цифры и `_`. Уникальность проверяется без учёта регистра при регистрации и при смене ника; если ник занят, бот отвечает «Этот ник уже занят… Попробуй другой».

## Интерфейс

Кнопки правят текущее сообщение (подпись под логотипом или текст), а не присылают новое фото. Новое сообщение отправляется только в ответ на ваш текст/команду или если старое нельзя отредактировать (удалено, подпись длиннее 1024 символов).


## Обновление каталога через JSON

В панели кастомизации нажмите «Обновить через файл». Бот отправит `nethershop_catalog.json`. После редактирования отправьте файл обратно с тем же именем.

Формат файла — объект категорий. Ключ категории — технический идентификатор (латиница, цифры, `_` и `-`), `button` — подпись кнопки в каталоге, `items` — список товаров в формате `[название, количество в порции, цена порции]`.

Пример:

```json
{
  "gear": {
    "button": "Экипировка и PvP",
    "items": [
      ["Алмазный меч", 1, 32],
      ["Берёза", 64, 2]
    ]
  },
  "blocks": {
    "button": "Блоки и материалы",
    "items": [
      ["Камень", 64, 5]
    ]
  },
  "plants": {
    "button": "Растения",
    "items": [
      ["Саженец дуба", 16, 3]
    ]
  }
}
```

Категории и товары, отсутствующие в загруженном полном файле, скрываются из каталога, но записи товаров не удаляются физически. Раздел «Головы» системный и в JSON не включается.

## Оплата заказов

1. Исполнитель нажимает «Заказ готов» — клиенту приходит сообщение, что заказ в пункте выдачи, и сколько алмазов (аб.)
   нужно оставить в одном из сундуков, в котором лежит его заказ. Эта сумма сразу попадает в долг в профиле клиента.
2. Клиент забирает заказ и нажимает «Забрал заказ» в «Мои заказы». Заказ **не исчезает**, а получает статус
   «Проверка оплаты» и остаётся в разделе «Выполнить заказ» у всех исполнителей и глав.
3. Сотрудник проверяет сундук и нажимает под заказом «Подтвердить оплату». Заказ удаляется, долг клиента гасится,
   сумма записывается в «Потрачено за всё время» в профиле и в статистику.

Долг не хранится отдельным числом, а считается из заказов в статусах «Прибыл в пункт выдачи» и «Проверка оплаты».
Поэтому отмена заказа исполнителем (до того, как клиент его забрал) тоже снимает долг. Заказ без суммы
(только головы, цена которых согласуется в ЛС) закрывается сразу после «Забрал заказ». Если клиент забыл нажать
«Забрал заказ», исполнитель, доставивший заказ, может подтвердить оплату прямо из статуса «Прибыл в пункт выдачи».
Новых миграций для этого не нужно.
